# PCB Studio

Use PCB Studio when the result is an electrical design, circuit board, bill of materials, sourcing workflow, or manufacturing handoff—not merely a picture of a board.

## Native model

PCB Studio owns the complete design engine. Its canonical source is `apteva-pcb/v1`: deterministic JSON with integer-nanometre geometry, integer-microdegree rotations, stable object IDs, layers, components, pins, native footprint pads and bodies, nets, net classes, electrical models, simulation sources and probes, copper traces, vias, zones, keepouts, differential-pair constraints, and manufacturing rules. It does not call KiCad, Flux, tscircuit, or another ECAD engine.

Every edit creates an immutable revision. Start with `pcb_examples`, then:

1. Create a board with `pcb_designs_create`.
2. Edit it with `pcb_operations_apply` for normal changes, using the current revision as `expected_parent_id`. Use `pcb_revisions_create` when replacing the complete definition.
3. Add native `body` and `pads` geometry to every component, plus `zones`, `keepouts`, and `differential_pairs` where the board needs them.
4. Use `pcb_route_suggest` to review a deterministic routing plan, then `pcb_route_apply` to commit it as an immutable revision. `pcb_route_selected` and `pcb_route_all` are convenient routing entry points; `pcb_route_remove` only removes traces and vias generated by the native router.
5. Run `pcb_validate` and resolve every error. To validate against a fab's process, list profiles with `pcb_fab_profiles` and apply `fab_profile.select` (built-ins: `jlcpcb-standard-2l`, `jlcpcb-standard-4l`, `pcbway-standard`, `oshpark-2l`; reference values, confirm with the fab). A profile only tightens design rules; net classes still apply on top. The validator checks frozen footprint provenance, exact rotated pad polygons, pin mappings, solder-mask slivers, paste apertures, plating and slots, annular rings, via-to-via/trace/pad clearance, polygonal board edges, keepouts, routing connectivity, and differential-pair gap/skew.
6. Save a `simulation` block with `simulation.set`, or pass an override to `pcb_simulation_run`. Use `pcb_simulation_probe`, `pcb_simulation_fault_set`, and `pcb_simulation_compare` for rail, transient, digital, and fault experiments. For a load-step test add a source with `kind: "load"` (Value in amps, `start_us`, optional `end_us`) on a regulator output; the result's `load_steps` reports the dip, minimum voltage, and recovery time. Regulator models accept `output_resistance_ohms`, `response_time_us` and `max_current_a`; output capacitance comes from capacitors on the rail. Use a small `step_us` to see the dip in the waveform. Results and waveforms are persisted through Storage.
7. Use `pcb_firmware_run` for Arduino-compatible behavioral execution against virtual board hardware. The runtime handles globals, `#define`, user functions, `if`/`else`, `for`, `while`, arithmetic and logic, `digitalRead` / `analogRead` (drive them with `digital_inputs` / `analog_inputs`), `millis`/`micros`, `map`/`constrain`, serial, GPIO, I2C and modeled sensors; anything else is counted in `unsupported`. `pcb_firmware_header` writes `board_pins.h` (`PIN_<NET>` per MCU GPIO), and those constants are predefined in the runtime. Store the board's firmware with the `firmware.set` operation (`source`, `expect_serial`, inputs) so readiness can run it. Set `executor_function` only when a bound first-party Functions toolchain should compile or execute the sketch.
8. For physical tutorials, inspect `pcb_wiring_library`, create the Arduino starter with `pcb_wiring_example_create`, or use revisioned `wiring.*` operations. Run `pcb_wiring_validate`, then `pcb_wiring_simulate` to map GPIO state to parts. Export SVG, PNG, tutorial JSON, or tutorial ZIP with `pcb_wiring_export`.
9. For enclosure handoff, create the Raspberry Pi 4 reference with `pcb_mechanical_example_create`, or add a revisioned `mechanical` block with `mechanical.set`. Run `pcb_mechanical_validate`, inspect it in the Mechanical workspace or create an SVG with `pcb_mechanical_preview`, then export an immutable `apteva-mechanical-envelope/v1` artifact with `pcb_mechanical_export`. Use `pcb_mechanical_solid_export` for a named AP242 STEP assembly, STL/3MF reference mesh, or authoritative DXF profile.
10. Use the Layout workspace for snapped component placement, 90-degree rotation, nudging, manual trace/via authoring, selection/deletion, and undo/redo. Save the staged board as a new immutable revision before running server actions.
11. Use `pcb_render` for the footprint-aware SVG and `pcb_bom_generate` for the grouped BOM. Run `pcb_manufacturing_verify` to independently parse and reconcile the generated Gerber X2, Excellon, and Gerber-job data; `pcb_manufacturing_generate` creates the gated manufacturing ZIP.
12. Use `pcb_kicad_export` and `pcb_kicad_verify` for KiCad board compatibility, or `pcb_kicad_import` to create a native design from `.kicad_pcb` content. The native revision remains authoritative.
13. Run `pcb_production_readiness` before a prototype order. It combines DRC, Gerber/Excellon parsing, KiCad reconciliation, footprint/MPN/model coverage, mechanical validation, test-point coverage, the firmware gate (stored firmware runs cleanly and prints `expect_serial`), the sourcing gate (latest `pcb_bom_source` stock check), and physical validation. `pcb_release_overview` returns all gates, package contents, sourcing, bring-up and orders in one call.
14. Record why parts and nets were chosen with `annotation.set` (`component_id` or `net_id`, `annotation: {reason, datasheet_ref}`); the BOM carries both columns.
15. After boards arrive, get the measurable plan with `pcb_bringup_plan`, then record results per board with `pcb_bringup_record` (`value` for resistance and voltage checks, `passed` for inspection and firmware). Physical validation passes when one board passes every required check, and readiness becomes `ready_for_production`.
16. Use `pcb_release_create` to make a traceable ZIP with native source, validation, Gerber/Excellon, KiCad exchange, STEP when available, verification reports, readiness report, bring-up plan, SVG, BOM, and hashes. Failed DRC or parser verification blocks release creation. Releases include the pick-and-place CSV, assembly BOM, structured bring-up plan, and firmware with its pin header; `pcb_assembly_generate` creates the assembly files on their own.
17. To order boards, run `pcb_order_prepare` (fabricator, quantity, assembly) to build the verified upload package, upload it at the fab, then record the fab's quote, order number, status and tracking with `pcb_order_update`. `pcb_orders_list` shows the history.

## Schematic

A revision may carry an optional `schematic` block: sheets, symbol instances (`component_id`, `symbol_id`, `sheet_id`, position, `rotation_deg`, `mirror`, `unit`), wires, net labels (`local`, `global`, `power`), and junctions, in integer nanometres on a +Y-down sheet with a 1.27 mm grid. The net list stays authoritative; the schematic is checked against it.

- `pcb_schematic_generate` (with `expected_parent_id`) places one built-in symbol per component (`apteva:R`, `apteva:C`, `apteva:LED`, `apteva:D`, `apteva:CONN`, generated `apteva:IC` boxes) and connects every net with labels, using power flags for rails such as GND, VCC, +3V3 and 5V. Pass `replace_existing` to regenerate over an existing schematic.
- Edit it with `pcb_operations_apply`: `schematic.set`, `schematic.symbol.place` (add or move; omit `symbol_id` to keep the current symbol), `schematic.symbol.remove`, `schematic.wire.add`/`remove`, `schematic.label.add`/`remove`. `pcb_examples` lists the built-in symbols and pin conventions under `schematic`.
- `pcb_schematic_get` returns resolved symbols, pin anchors and the schematic ERC. ERC (`SCH_*` checks, also part of `pcb_validate` when a schematic exists) reports missing symbols, missing or extra connections per net, dangling wires and labels, and unconnected input pins.
- `pcb_kicad_schematic_import` attaches a single-sheet KiCad 6–8 `.kicad_sch` to a design. Symbols map to components by reference designator and pins by pin number. The report lists matching nets, nets only in the schematic, and nets only on the board. `replace_nets` rebuilds the net list from the schematic, keeps the IDs of nets that already match, and refuses to drop nets that carry routing. Hierarchical sheets and buses are not supported.
- `pcb_schematic_render` stores an SVG of one sheet.

## Automatic placement

Place parts before routing. `pcb_placement_analyze` reports courtyard/body overlaps, keepout, cutout and mounting-hole conflicts, off-board or edge-clearance pads, parts whose `panel_openings` face (north/south/east/west) is not at that board edge, and the total ratsnest (per-net MST) length. `pcb_placement_suggest` returns a deterministic plan of `placement.set` operations with before/after analysis; `pcb_placement_apply` commits it as an immutable revision and emits `pcb.placement.completed`.

- Options: `component_ids` (subset to move; default every non-fixed part), `fixed_component_ids`, `grid_nm` (default 0.5 mm), `allow_rotation` (90° steps, default off), `allow_back_side` (through-hole parts only; pads are never mirrored), `edge_margin_nm`, `spacing_nm` (routing channel between parts, default 1 mm), `panel_edge_tolerance_nm` (default 3 mm), `improvement_passes`, `clear_routing`.
- Set `"fixed": true` on a component to keep it where it is. Parts with an edge panel opening slide only along their face. Mounting holes, cutouts, zones, and keepouts are obstacles; differential-pair chains are placed on one shared line so the pair can run straight.
- Keepouts owned by a part (`owner_id`) and its mechanical envelopes, panel openings, and clearance volumes move rigidly with it (`keepout.remove`/`keepout.add` and one `mechanical.set` in the plan).
- Moving parts strands their existing copper: the plan lists `stale_routing_nets`. Pass `clear_routing: true` to remove that copper in the same revision, then route with `pcb_route_all`.

## Component data and sourcing

Local component, footprint, pin, and MPN fields remain authoritative. If the optional `component_data` provider (Nexar/Octopart) is bound, `pcb_components_search` searches parts and `pcb_bom_source` checks stock and price for every revision MPN (pass `build_quantity` for the number of boards). It stores a sourcing summary that feeds the sourcing readiness gate and a priced BOM CSV. Provider results enrich a design but never mutate it automatically.

All dependencies are native install bindings. The required `storage` role selects a project or global Storage app install (`kind: app`); the optional `firmware_executor` role selects Functions (`kind: app`); `component_data` and `pcb_fabricator` select external connections (`kind: integration`). Do not bypass these roles with connection IDs or assumed app installations.

## Compatibility

The native source remains the editable truth. Import/export compatibility is implemented as deterministic Apteva-owned adapters around that model. V0.9 reads and writes KiCad boards, writes AP242 STEP assemblies, and reconciles generated exchange geometry against the native revision without invoking KiCad or a CAD engine. The mechanical envelope and DXF remain authoritative for holes, cutouts, interfaces, and tolerances. Third-party project adapters remain compatibility layers, never runtime engines.

No fab in the integration catalog publishes a quote or order API yet, so PCB Studio prepares and verifies the order package and records what the fab returns. A paid order is always placed by a person at the fab.
