# PCB Studio

PCB Studio is Apteva's native electronics-design app.

The fabrication set is a full Gerber X2 stack: numbered copper (inner layers included), solder mask, paste, silkscreen, an arc-exact Edge_Cuts profile, separate `drill/board-PTH.drl` and `drill/board-NPTH.drl` programs with G85 slots, and `board.gbrjob`. `pcb_panelize` builds V-score or mouse-bite-tab production panels with rails, fiducials and tooling holes as a separate verified artifact.

Version 0.11.1 fixes library footprints being written mirrored top-to-bottom (pin order clockwise) in Gerber, pick-and-place and KiCad output. Library pads are now converted from KiCad's +Y-down frame to the board's +Y-up frame at placement; the board previews, the 3D view and KiCad export/import use the same frame. Designs with parts placed by 0.11.0 fail DRC with `FOOTPRINT_FRAME_LEGACY` until the `component.reframe_library` operation is applied and the affected nets are re-routed.

Version 0.11 targets assembled boards. Releases add JLCPCB-format CPL (with per-package rotation offsets) and BOM files; `pcb_lcsc_match` fills LCSC part numbers by MPN or, for resistors and capacitors, by value and package. A built-in parts library (pogo pin, Qwiic, ESP32-S3, LiPo charger, PIR, OLED, encoder, relay and more) and `pcb_footprint_import_kicad` replace hand-drawn pads. Fab output gains mask and paste layers, PTH/NPTH drill files with slots, roundrect/oval/custom pad shapes, rounded board corners and inner copper layers, and `pcb_panelize` builds production panels. The router routes at 45 degrees with rip-up and retry. DRC flags I2C address conflicts on a board and, with `pcb_i2c_bus_check`, across blocks sharing a bus. Designs can be copied or marked as templates whose outline and fixed parts sync to derived blocks. The firmware runtime adds I2C reads, WiFi, LEDC PWM, deep sleep and other ESP32 calls.

Version 0.10 closes the design-to-delivery loop. `pcb_placement_suggest`/`pcb_placement_apply` place parts automatically (edge connectors on their panel edge, differential-pair chains aligned, everything else by connectivity) and the router now routes multi-pad nets as spanning trees with layer-correct endpoints. A schematic workspace generates sheets from the net list, runs ERC against the board nets, renders SVG and imports KiCad `.kicad_sch`. Fab rule profiles (JLCPCB, PCBWay, OSH Park reference values) tighten DRC; releases include a pick-and-place CSV and assembly BOM; `pcb_bom_source` stores stock and price per MPN and feeds a sourcing gate; simulation adds regulator load steps; firmware runs on a behavioral Arduino interpreter with `PIN_<NET>` constants and a firmware gate; bring-up measurements per board feed the physical-validation gate; and fab orders are packaged and tracked (prepared → quoted → placed → shipped → delivered). Placing the order itself still happens on the fab's site — no fab exposes an ordering API this app can call. The panel adds Schematic and Release workspaces.

Version 0.9 turns the routed ESP32-C3/DHT22 board into a production-prototype fixture. Every populated component carries a frozen footprint revision, source hash, pad/pin count, courtyard, solder-mask/paste intent, compatible MPNs, and—where mechanically relevant—a versioned native 3D model contract. The geometric DRC now checks actual rotated pad polygons, mask slivers, via-to-via/trace/pad clearance, annular rings, slots, plating declarations, and polygonal board-edge clearance.

V0.9 also adds deterministic KiCad `.kicad_pcb` import/export with an independent structural reconciliation pass, AP242 faceted-BREP STEP assembly export, and an `apteva-pcb-production-readiness/v1` gate. Release ZIPs now include native source, Gerber/Excellon, KiCad exchange, both verification reports, STEP when mechanical data is present, a readiness report, and a physical bring-up plan. Four accessible DHT-board test points cover USB 5 V, 3.3 V, ground, and DHT data. The gate deliberately reports physical validation as pending until real boards are ordered and tested.

Version 0.5's physical Wiring workspace remains available for Fritzing-style Arduino and breadboard tutorials, with an engine-independent part/pin/wire model, reference library, electrical compatibility checks, Arduino-to-physical-pin simulation, and deterministic SVG, PNG, tutorial JSON, and tutorial ZIP exports. Version 0.4's direct board editing, independent fabrication-file verification, autorouter, DC/RC/digital simulation engine, and Arduino-compatible virtual microcontroller lab also remain available.

These capabilities build on the native manufacturing foundation: canonical `apteva-pcb/v1` source, typed operation batches, component bodies and footprint pads, net classes, copper zones, antenna/copper/component keepouts, differential-pair intent, connectivity-aware ERC/DRC, semantic diffs, footprint-aware SVG rendering, deterministic BOM generation, and traceable release ZIPs.

It has no external ECAD, routing, or simulation engine dependency. Storage and other first-party apps are selected through native `kind: app` bindings; external component-data, sourcing, fabrication, and assembly providers use native `kind: integration` bindings. The optional `firmware_executor` binding can delegate full toolchain compilation/execution to the first-party Functions app, while the built-in behavioral runtime stays available without it. The core model remains independent of every bound target.

## Develop

```sh
GOWORK=off go test ./...
bun run scripts/build-panels.ts --app pcb
```

The panel combines the source editor with interactive Layout, Wiring, and Mechanical canvases and dedicated Route, Simulate, and Firmware workspaces. The Raspberry Pi starter creates an enclosure-ready mechanical reference programmatically; its immutable revision drives validation, 3D display, envelope, DXF, and STEP export. The routed DHT22 starter exercises frozen footprints, test points, fabrication parsing, KiCad exchange, and the production gate. The Arduino Uno + LED starter creates a semantic tutorial programmatically. Native writers and parsers produce every artifact without invoking Fritzing, KiCad, Flux, or another ECAD engine; KiCad is a compatibility format, not a runtime dependency.

Manufacturing output is gated twice: first by native ERC/DRC, then by a separate parser that checks file syntax, termination, bounds, aperture use, arc radii (G75 G02/G03), region closure, geometry counts, solder-mask openings and paste apertures per side, copper layer numbering, PTH/NPTH holes and G85 slots, outline edges, and Gerber-job file functions. A pad-aware design must route each net node through a same-net trace or zone; invalid pad/drill geometry, copper clearance, keepout incursions, differential-pair gap/skew, incomplete routing, or malformed generated files block manufacturing and release creation. Autorouting never bypasses these checks. Designs created before v0.2 remain readable but receive explicit missing-pad-geometry warnings until upgraded.
