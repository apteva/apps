# Editable AdultFolio actor

Import `adultfolio-control.json`, then set `defaults.context_id` to the saved Computer login context and `defaults.account_url` to the authenticated account's canonical profile URL, and `defaults.account_profile_path` to that URL's path (for example `/YOUR_ACCOUNT_PROFILE`). All provider selectors and workflow policy are in this editable example. No credentials or real account IDs are shipped.

Operations:

- `inspect_page` / `inspect_controls`: verified account, current URL and visible semantic controls/navigation. Optional `page_url`.
- `get_search_options`: native profile, distance, ordering, gender, country, message-history, region and town options, with ordered value/label arrays; also returns the hidden location-mode value.
- `search_unmessaged_models_by_country`: required `country_code` from `get_search_options`; optional `gender_code` (`F` female, the default; `M` male), and `read_pages`. Searches new prospects outside this account's message history using verified country mode. No custom URL is needed.
- `search_models`: `model_query`. Reads the native autocomplete model suggestions, with numeric ID, name, thread URL and `profile_lookup_operation:"search_exact_model"`. The query is verified from the live input before candidates are emitted. The result is explicitly bounded/non-exhaustive; use exact lookup to verify the selected canonical profile, and country/age search for outreach eligibility.
- `search_exact_model`: `model_query` containing the complete, case-exact profile name. Uses native autocomplete, requires one unique model suggestion, verifies its numeric ID, then opens and verifies the actual profile URL, exact heading name and independent message ID/URL. It changes search-field state and follows navigation only; it never sends a message. Missing, ambiguous or non-model suggestions fail instead of implying absence.
- `list_conversations` / `list_threads`: inbox conversations, deduplicated by numeric model ID. AdultFolio has one conversation per correspondent.
- `list_messages` / `get_thread`: `model_id`, `model_url`. Verifies the requested correspondent and reads older messages. An observed empty returned batch marks end-of-history even if the older control remains visible; unchanged IDs without that marker remain incomplete. Returns server message IDs, sender URL, incoming/outgoing direction, timestamps, body and attachment/image URL arrays. Messages are emitted in discovery order; sort by `sent_at` and numeric ID for a chronological display.
- `prepare_reply`: `model_id`, `model_url`, `message`. Fills and verifies the real visible composer; never clicks Send.
- `reply`: the same inputs plus a stable `request_id`. Revalidates account, thread, recipient and exact composer text. Sends once through a fresh semantic target, reloads the conversation, and verifies a new server message ID, the outgoing account and exact saved text. A reserved/uncertain request ID must never be automatically replaced with another ID to retry.
- `verify_reply`: `model_id`, `model_url`, `message`, `baseline_message_id`. Read-only recovery check after an uncertain send. The baseline must be the last server message ID seen before sending.

Read coverage is explicit. `inspection_complete=false` or `more_results_remaining=true` means absence was not proved. Consumers must read all dataset cursors and inspect coverage even if the run failed. Bounded inbox/history reads return successful partial datasets with `inspection_complete=false` and `more_results_remaining=true`. Identity, inaccessible-view, changed-collection, timeout or truncated-HTML failures remain failures; login/identity changes, unverified empty views, ambiguous controls remain failures. A verified pagination stall can return a partial dataset under the explicit policy below. Large name queries may exceed the rendered-HTML limit; narrow the query instead of treating failure as no results. `read_pages` (default 5), `max_pages`, `max_items` and `max_duration_seconds` can be supplied as inputs for bounded previews or full inspections.

This example intentionally has no sample recipient or message. Live sends require an explicitly selected recipient and approved message. Reply confirmation checks are independent of the effect guard: a click alone is never reported as a saved reply.

For female models in Spain this is the complete search request (the country is caller input, never a configured account default):

```json
{
  "operation": "search_unmessaged_models_by_country",
  "input": {"country_code": "ES", "gender_code": "F", "read_pages": 2}
}
```

The assigned login context and account are inherited. `country_code` is required and case-sensitive; discover supported codes/labels with `get_search_options`. The gender defaults to `F` (female); pass `M` for male models. Message exclusion is built into this named operation; no additional flag is necessary. Results contain `record_type:"model"`, `model_id`, `model_name`, `profile_url`, `thread_url`, `role`, `location`, `location_status`, `requested_country_code` and `messages_filter:"exclude"`. A missing/blank card location becomes `location:"unavailable"`, `location_status:"unverified"`; do not treat that candidate as individually location-verified. `location_status:"reported"` means the text was read from that card, not that its country was independently verified. Keep the full location text: some countries show city/country, while UK cards show city/county. Use the verified filter evidence and readable card locations when presenting geographical results.

A separate filter-evidence row (without `model_id`) records the authenticated `account_url`, `country_code`, `country_label`, `gender_code`, `location_mode`, `messages_filter`, `profile`, and nonempty selected `region`/`town` code arrays. A completed run asserts the requested country/gender, `location_mode:"0"`, `messages_filter:"exclude"`, models only, and unrestricted region/town. AdultFolio can leave stale London postcode values in the inactive radius fields; mode 0 is what activates the country filter. A failed guard means its dataset is diagnostic, not a verified search result. `read_pages:2` is a preview; check `output.coverage.inspection_complete` and `more_results_remaining` before claiming the whole search was checked. The provider's exclude filter means this account has not messaged those members; it is not evidence about other accounts or whether a member has contacted you.

`search_filtered_models` accepts an explicitly constructed `search_results_url`, using values returned by `get_search_options` (the profile value for models is `model`, not `models`). This is an advanced operation: country searches must explicitly set `do_postcode_search=0`, `location=` and `town=`; `country` alone can leave radius mode active. Prefer the named country-search operation above for new prospects. The default bounded reads are suitable for recent conversations/messages; a complete historical crawl may reach provider or HTML limits and must never be described as complete.

Keyword and filtered search readiness waits for result cards or explicit empty-state text, rather than the initially empty AJAX container. Message pagination waits five seconds after navigation and checks loading text. Some site histories leave their older-message control present after returning no new records; stalled reads wait for AJAX advancement without clicking again, then return the verified dataset with incomplete coverage. Consumers must not interpret that incomplete result as a complete conversation.

Message bodies exclude the provider's outer HTML indentation, preserving internal copy, case, spacing and line breaks. Reply preparation rejects leading/trailing whitespace in the requested copy before Send; saved verification applies the same boundary normalization.

Saved-reply verification uses the configured account profile path to select messages by the authenticated sender profile link and then reasserts its exact canonical URL. Delete controls are present on incoming messages too, so they are never used as evidence of outgoing direction.

The example uses a 1600×400 viewport to keep low-priority pagination controls within Computer's semantic-target budget. Pagination reveals older-message controls from the document start, and inbox/search controls from the end, with overlapping semantic observations. `advance_timeout_ms:20000` waits for new server records after each click; DOM reordering is not advancement. `allow_partial:true` plus `pagination.on_stall:"partial"` applies only to verified read-only collections and retains an explicit stall reason and incomplete coverage. This is never evidence that no older records exist. Strict operations keep the default failure policy. Message records now carry `record_type:"message"`, `model_id`, and `model_url`; conversation records carry `record_type:"conversation"`. Identity-guard rows have no record_type and should be excluded from the message/conversation arrays.

AdultFolio may return HTTP 500 for an exact keyword query while leaving its loader visible. Use `search_exact_model` for a known complete name instead of trusting an error-response body or weakening readiness. Broad keyword/filter searching remains separate. Autocomplete is selected through the role-label span inside the single verified selected model suggestion because this widget exposes no option target in SOM; search-input focus uses fresh SOM, and no coordinates are used. Direct heading text excludes nested membership badges without guessing badge names.

Exact lookup returns the observed profile URL as `current_url`; it does not infer a slug from the name or rely on head canonical tags omitted by rendered extraction. Final checks require an AdultFolio profile-shaped HTTPS URL, exact direct heading name, independent numeric message ID and unchanged account.

The exact suggestion name/ID and selected name/ID are verified before navigation. The click targets that selected row's unique `- model` span with an exact label/effect guard, because clicking the wider row can land on a child label whose live semantics differ from the row text. Independent destination checks follow; this operation never sends or modifies a profile.

Initial outreach uses `search_unmessaged_models_by_country_and_age`, then `screen_model_for_outreach`, then `initial_send`. `get_search_options` includes the live `lage`/`hage` options. Age inputs are their string values, for example `min_age:"18"`, `max_age:"39"`; country and gender remain runtime inputs. Search verifies the active bounds, country mode, gender and exclusion filter. The older country-only operation explicitly returns `age_screened:false` and is discovery only for an age-restricted process.

`get_model_profile_age(model_id,model_url)` follows the profile's verified native Info URL and returns the site's labelled integer age, role, country and message-history label. `screen_model_for_outreach` additionally requires `country_code`, the configured `expected_model_role` (default `Female Model`), inclusive `min_age`/`max_age` (example defaults 18–39), and native `No message history`. Missing/ambiguous ages, a different numeric model ID or canonical profile, wrong country/role, and an existing history fail. Ages are read from the profile; never infer them from photographs or search cards.

`prepare_initial_send` accepts the same screening inputs plus exact `message`. It verifies the account/thread, independently proves zero prior message IDs and blank thread content without older-message controls, fills the composer, reasserts exact copy and repeats the empty-thread check. It never sends. `initial_send` adds a stable `request_id`, guarded semantic Send and independent persisted-record verification after reopening the conversation. Use `reply` for an existing conversation; do not use it as fallback after initial-send failure.

`verify_initial_send(model_id,model_url,message)` is read-only reconciliation for a previously attempted initial send whose original run proved the conversation empty. Use the exact original run's immutable account/context/recipient/copy; the initial baseline is zero. It requires one outgoing server record with the exact saved body, account URL, positive message ID and timestamp. A fast incoming reply does not invalidate the saved outgoing evidence. Missing or multiple outgoing records fail and cannot authorize resending. Ordinary `verify_reply` still requires the existing-conversation baseline recorded before dispatch. Compare the saved ID with the original attempt's baseline and reconcile bookkeeping; neither verifier retries delivery or changes an uncertain effect guard.

Both send operations use `once_scope:"reply"` and the existing `reply:account:model:request` key. This preserves historical reply guards and prevents switching from `initial_send` to `reply` to replay the same logical request. Keep the original request ID across revisions; never replace it to bypass an uncertain outcome. A failed verifier means delivery is unresolved, not absent. A transport or explicit unsuccessful action result keeps the original attempt blocked while you inspect saved state.

Live-send acceptance requires a selected test recipient and approved exact copy. Preparation, profile/search reads and simulated persistence tests do not prove live delivery. Test both a genuine empty thread and an existing conversation on controlled accounts, then verify the saved server IDs. Simulate lost responses in fixtures rather than intentionally disrupting a live send.

Empty histories can have zero rendered height. Readiness waits therefore use the visible recipient heading and composer; strict raw-DOM extraction separately requires the correct history container and proves its content is empty. The last preparation observation returns `visible_controls`, including currently visible semantic targets, with the repeated empty-thread evidence. Never use repaired-run recovery for an ambiguous send: it requires proof of no commit. Use the read-only message verifier and reconcile the original logical request without unlocking or replacing its guard.

Native keyword snapshots require Actors 0.2.36+. All operations remain editable examples. Browser/account placeholders must be supplied by the installer.
# Everywhere and long messages

`search_unmessaged_models_by_radius_and_age` accepts `radius_miles:"9999"` for AdultFolio's Everywhere option, alongside the existing positive radii through 9000. It still asserts the live selected option, location, account, gender, age and exclude-messaged filter and reports bounded coverage.

Both `reply` and `initial_send`, and their preparation operations, reveal the exact **Send!** semantic target with bounded verified scrolling before rechecking the composer and recipient. They work with the 400px viewport and multiline messages without coordinate clicks. Preparation stops before sending. Existing uncertain sends retain their guards; this update never automatically replays an earlier request.
